# Architecture rules
- Incident asset references are resolved through the central entity registry with tenant-scoped query keys; this preserves stored UUID links and reuses canonical navigation without exposing raw identifiers.
- Integration catalog statuses and the connected section share the same tenant-scoped query through useConexoesAtivas; this prevents contradictory connection labels without enabling new connections.- Module side panels use the shared RecordDetailDrawer (KPIs, contextual alert, grouped sections, Links/Activity tabs, prev/next); link data comes from tenant-scoped hooks in useDetalheLigacoes, so every module keeps one visual pattern.
- Long-running AI analyses (document adherence) run as tenant-scoped job rows processed in short self-invoking slices with a DB lock; this avoids edge timeouts for any document size.
- List/grid views reuse the same DataTable columns, sorting, pagination and row actions; this prevents divergent results across representations.
- Module tab bars use ModuleSubbar with the existing list search state; this keeps local filtering distinct from global search.
- OwnerCell and RecordProgress are shared record-cell presentations; progress accepts measured values only, never inferred workflow percentages.
- Supplier tab counts use useSupplierCount rather than assessment-email counts; this keeps navigation aligned with the actual supplier list.
- A Card nested in another Card loses its frame via global CSS (`data-slot="card"`; opt out with `data-keep-frame`); this keeps one rounded border per area.
- Form drafts use useWizardDraft with keys scoped by empresa + user, and deletes use undoableAction (commit after the undo window); this keeps drafts tenant-isolated and deletions reversible.
- Requirement answer drafts contain only edits and the saved-answer fingerprint; restore only against the same saved answer, rejecting legacy snapshots, so colleague and bulk updates remain authoritative.
- Gap Analysis requirement editing lives only on the full page /gap-analysis/framework/:frameworkId/requisito/:requirementId (RequirementDrawer asPage, which also hosts evidence reuse, review/exception and action-plan sections); legacy ?req= links redirect there and the framework page has no local ⌘K, so there is one shareable editing surface and one search.
- Global requirement catalogue quality is self-healed by the populate-requirement-guidance cron (expands title-only descriptions, rewrites guidance lacking the ordered-steps section) and the drawer renders guidance via parseOrientacao sections; this keeps every framework instructive without manual data fixes.
- Akuris-team tools live on /admin-akuris (super-admin only); /configuracoes holds only customer settings, so tenant admins never see platform tooling.
- Module permissions are assigned only through permission profiles (user_module_permissions is derived from the profile); there is no per-user override UI, keeping access reviews tractable.
- Every DataTable offers the standard Export menu (CSV/PDF of the filtered rows); modules with custom CSV pass it via onExport instead of their own header button.
- Judgement-heavy AI (evidence, documents, diagnostics, DocGen, questionnaires, supplier/risk suggestions) uses MODELOS.ANALISE; chat/quick tasks stay on PADRAO, so quality spend goes where users decide on the output.
- Every AI Gateway call goes through _shared/ai.ts helpers (fetchIA, fetchAnaliseComReserva, callAiGateway), which log model, tokens, latency and fallback to ia_uso_modelos (super-admin read); Financeiro IA costs come from that log, not from credit rows.
- Project tabs share one visual vocabulary from components/projetos/projeto-visual.tsx (code chip, phase/domain/activity level, avatar) and StatusPill; this keeps Lista, Kanban, Gantt, Calendário, Sprints and Métricas consistent.
